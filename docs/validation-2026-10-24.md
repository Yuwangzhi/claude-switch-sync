# macOS 切换后启动即退出：修复验证

验证日期：2026-10-24。客户端组合为 Claude Desktop 3.6556.2、Claude Code 2.1.309、CC Switch 4.0.15。

## 原因

从官方订阅直连切换到 DeepSeek 路由后，App 日志显示第三方 gateway 配置健康，随后收到正常退出请求。同步服务则反复记录 `Conflicting transcript IDs`，没有完成切换。

两侧同一会话的 `cliSessionId` 不同，但较新索引的 `priorCliSessionIds` 明确包含较旧的 ID，会话 ID、创建时间和项目目录也一致。这是可确认的续聊关联。旧脚本把所有 ID 变化都视为冲突，又在错误重试时反复请求退出 App，造成打开即退出的现象。

## 修复

- 识别明确记录的 CLI 会话 ID 换代，仍保留完整索引记录和原始备份。
- 对无法确认关联的记录保留两侧版本，不阻止其他会话同步。
- 每次切换的退出请求在发送前写入状态，重试和后台服务重启不重复关闭 App。
- 合并失败时恢复刚关闭的 App，等自然退出再重试。
- 用户切回原供应商时清除过时的待处理状态。

## 验证结果

- 21 项隔离回归测试全部通过，覆盖双向合并、分支冲突、预期及意外异常的应用生命周期恢复。
- 当前切换成功合并 164 条会话索引，未决关联数为 0，状态中没有 `pending`、`last_error` 或 `last_warning`。
- 两侧会话 JSON 和归档索引一致；原有删除标记各自保留。
- 核对原有 266 份正文：均未丢失，原始字节完整保留。App 在验证启动/退出过程中给其中两份追加了 `cost-state` 元数据，不能把整个验证过程描述为所有文件哈希不变。
- Claude App 在 DeepSeek 路由下重新打开，日志加载 160 条普通会话和 4 条归档会话。界面显示历史会话、输入框和 `DeepSeek V4.1 Flash-1017` 模型入口。
- 同步仍由文件/进程事件触发，没有启用周期复制。
- 仓库中的安装脚本已在当前部署上完成升级验证：源码与部署文件一致，LaunchAgent 运行正常，升级没有重启正在打开的 Claude App。

本次没有向已有研究会话发送测试提示，也不把“窗口正常打开”描述为新的模型推理测试。供应商、账户标识、聊天正文、凭据、原始日志和本机运行状态不纳入仓库。

## 官方订阅与第三方分别保留模型、推理选择

旧合并逻辑把最近活动的整个会话索引复制到另一侧，连同顶层 `model` 和 `effort` 一起覆盖。第三方续聊后切回订阅，官方会话因此可能显示第三方使用的模型别名和推理强度。

现在仍按最近活动记录衔接聊天进度，再保留目标侧原有的 `model`、`effort`。字段缺省和显式 `null` 都保留原状态；首次导入到另一侧时使用目标客户端的默认设置。历史中的模型使用信息继续随聊天进度同步。

- 26 项回归测试全部通过。新增 5 项覆盖往返切换、目标侧默认值、双向首次导入、显式空值，以及历史模型信息与当前选择的分别处理。
- 对当前两侧各 164 条真实会话索引制作隔离副本，依次执行官方到第三方、第三方到官方、再次官方到第三方的合并。每条会话在各侧的模型与推理选择始终保持原值，其他聊天进度一致；末次合并写入数为 0。
- 副本验证前后，实际会话索引的字节保持一致。
- 已通过 Claude App 的模型菜单恢复两条受影响的官方会话，界面分别显示 Sonnet 5.5 Medium、Sonnet 5.5 High，并核对了保存后的索引字段。
- 已运行安装脚本更新部署，源码与运行文件一致；LaunchAgent 处于运行状态，Claude App 进程保持不变，服务没有待处理切换或错误。

本轮新增合并规则通过隔离副本验证，尚未重新执行真实供应商往返切换；现有 App 会话保持打开。
